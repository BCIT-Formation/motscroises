# SHARED-CONVENTIONS.md

Org-wide reference conventions for BCIT-Formation repositories. The hard rules live in [CLAUDE.md](CLAUDE.md); this file carries the supporting detail. The canonical copy is maintained in the `claude-skills-bcit` repository (`templates/`); do not edit this file locally, propose changes there instead.

## Standard repository files

Every active repo maintains:

| File | Purpose |
|---|---|
| `README.md` | Project documentation, kept in sync with the code |
| `CLAUDE.md` | AI/human working rules + project specifics |
| `TODO.md` | Prioritised backlog: 🔴 critical / 🟠 important / 🟢 nice-to-have |
| `DECISIONS.md` (or `docs/ADR.md`) | Architecture decision records; one entry per architectural choice or new dependency |
| `SECURITY.md` | Disclosure policy and security notes |
| `CHANGELOG.md` | Auto-generated by release-please; never edit manually |
| `.env.example` | Config template with placeholders only |

Update documentation in the same PR as the code it describes.

## Code style

- Python: PEP 8, type hints, Ruff (line length 100), pytest. Format and lint before commit.
- JavaScript/TypeScript: npm (not yarn/pnpm), ESLint with zero warnings, Prettier. Prefer built-in runners (`node:test`) and vanilla JS over frameworks when reasonable.
- Kotlin/Android: Kotlin only, Gradle wrapper pinned, versions centralized in `libs.versions.toml`, JDK 17.
- Errors: catch specific exceptions, never bare `except:` / empty `catch`. Fail fast at system boundaries, trust internal contracts.
- Logging via a proper logger (never `print`), configurable `LOG_LEVEL`; long-running services expose `/health`.

## Testing details

- Coverage target ~80% on business logic; pragmatic, not dogmatic. UI/CLI glue layers are not unit-tested.
- Keep parseable logic in importable functions so it can be tested without the UI/CLI layer.
- No flaky or `@Ignore`d tests in `main`.

## CI/CD (GitHub Actions)

Standard workflow set:

| Workflow | Role |
|---|---|
| `ci.yml` | lint, test, build on every PR |
| `pr-check.yml` | Conventional Commit PR-title lint |
| `security.yml` | weekly CodeQL + gitleaks + dependency audit |
| `release.yml` | release-please: semver + CHANGELOG from Conventional Commits |
| `auto-merge.yml` | auto-approve + squash-merge `claude/**` and Dependabot PRs once CI is green |

Dependabot runs weekly. New workflows run on Blacksmith runners (`blacksmith-4vcpu-ubuntu-2404`).

## Security details

- Rate-limit authentication endpoints (~5-10 attempts per 15 min).
- Password hashing: PBKDF2 or argon2 with timing-safe comparison.
- `.gitignore` always covers: `.env`, `*.jks`, `*.keystore`, local DB files, `.claude/`.
- Secret scanning (gitleaks) in CI; keystores delivered via GitHub Secrets (`KEYSTORE_BASE64`).

## Docker (if applicable)

Multi-stage builds (deps, builder, slim runner), non-root user, `HEALTHCHECK` on `/health`, `docker-compose.yml` with `restart: unless-stopped`, `.dockerignore` excluding `node_modules`, `.env`, `.git`. Local dev: copy `.env.example` to `.env`, then `docker compose up`.
